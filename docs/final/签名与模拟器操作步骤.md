# 签名、模拟器与推送操作步骤（Windows / DevEco Studio 5.0.13）

> 目标：签出可安装的 HAP、在模拟器上真实执行 T1–T8、把仓库推上 GitHub。

## 0. 顺序不要搞反（实测踩过）

DevEco 5.0.13 的**自动签名需要先有设备**：它会用设备 UDID 去华为服务器申请 profile。设备没连上时，日志里是这句：

```
Unable to create the profile due to a lack of a device. Connect a device via IP or USB first.
```

结果就是 `build-profile.json5` 里的 `signingConfigs` 一直是空数组，构建继续 `Will skip sign`。

**正确顺序：登录 → 启动模拟器 → 自动签名 → 跑测试。** 先签名后启动模拟器会白点一次。

## 1. 环境对照

| 项 | 实际情况 |
|---|---|
| DevEco Studio | 5.0.13.240（`F:\DevEco Studio`） |
| SDK | HarmonyOS 5.0.5 / API 17，toolchains 完整（含 `hdc.exe`） |
| 工程 target/compatible SDK | 5.0.5(17) |
| 可用模拟器实例 | `F:\HUAWEImoniqi\Huawei_Phone`，HarmonyOS 5.0.5(17)，x86_64 |
| 不要用的实例 | `AppData\Local\Huawei\Emulator\deployed` 下的 Pura 90 Pro / Mate X7 等，是 API 26 且镜像目录缺失 |

## 2. 登录

DevEco 右上角头像 → **Sign In** → 浏览器登录华为账号 → 回 IDE 等提示成功。

## 3. 启动模拟器（必须在签名之前）

1. **Tools → Device Manager** → **Local Emulator**。
2. 列表里选 **Huawei_Phone** → 点启动（三角形）→ 等系统桌面出现。
3. IDE 的设备管理器配置已指向 `F:/HUAWEImoniqi`，实例应能直接列出。

若列表为空：**New Emulator** → Phone → 镜像选 **HarmonyOS 5.0.5（API 17）**。不要选 API 26。

## 4. 自动签名

1. **File → Project Structure…**（`Ctrl+Alt+Shift+S`）→ **Project** → **Signing Configs**。
2. 勾 **Automatically generate signature** → 同意协议 → **OK**。
3. 此时设备在线，才能取到 UDID 并生成 profile。

**成功判据**

- `build-profile.json5` 的 `signingConfigs` 由 `[]` 变为含 `name: "default"` 的对象；
- 重新构建不再出现 `WARN: Will skip sign 'hos_hap'`；
- 产物目录出现 `entry-default-signed.hap`。

若提示 `Failed to obtain the toolchains path ... install Toolchains on API 17`：
**File → Settings → OpenHarmony SDK**，把 SDK 路径指到 `F:\DevEco Studio\sdk`，确认 API 17 的 Toolchains 已勾选。

## 5. 确认设备

```bash
export MSYS_NO_PATHCONV=1
HDC="/f/DevEco Studio/sdk/default/openharmony/toolchains/hdc.exe"
"$HDC" list targets      # 期望 127.0.0.1:5555
```

为空时：`"$HDC" kill` 后重试，再不行就重启模拟器。

## 6. 执行 T1–T8

### IDE

打开 `entry/src/ohosTest/ets/test/FogEngine.test.ets`，点 `describe('FogEngine', ...)` 左侧绿三角 → Run，底部 **Test Result** 应显示 8 条通过。

### 命令行

```bash
cd "F:/AdvancedStateLab"
export MSYS_NO_PATHCONV=1
HDC="/f/DevEco Studio/sdk/default/openharmony/toolchains/hdc.exe"

"$HDC" install -r entry/build/default/outputs/default/entry-default-signed.hap
"$HDC" install -r entry/build/default/outputs/ohosTest/entry-ohosTest-signed.hap

"$HDC" shell aa test -b com.example.campuscardlab -m entry_test \
  -s unittest OpenHarmonyTestRunner -s timeout 60000
```

模块名是 `entry_test`（见 `ohosTest/module.json5`），不是 `entry`。

## 8. 推送到 GitHub（当前 HTTPS 通道不通，走 SSH）

实测：`github.com:443` 经系统代理返回 **502**，直连超时；但 `github.com:22` 的 SSH **可以直连**（握手成功，只是没有注册公钥）。所以用 SSH。

**本机已生成密钥**（无口令）：

- 私钥 `C:\Users\Administrator\.ssh\id_ed25519`
- 公钥 `C:\Users\Administrator\.ssh\id_ed25519.pub`

公钥内容：

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIAMN5So4IuVK5g+J/OLfFPodM9G2YZZENursfs8lqoiq li2-hub@fog-archive
```

**你要做的一步**：打开 https://github.com/settings/keys → **New SSH key** → Title 填 `fog-archive` → Key 粘贴上面整行 → Add SSH key。

然后（远程已配好为 SSH）：

```bash
cd "F:/AdvancedStateLab"
git push -u origin main
```

期望：`branch 'main' set up to track 'origin/main'`，仓库页出现 5 个提交。

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 勾了自动签名仍失败 | 设备未连接（生成 profile 需要 UDID） | 先启动模拟器，再回来勾 |
| 仍提示 toolchains 路径 | IDE 的 SDK 路径未指向 `F:\DevEco Studio\sdk` | Settings → OpenHarmony SDK 重设 |
| `hdc list targets` 为空 | 模拟器没起 / hdc 服务卡住 | `hdc kill` 后重试或重启模拟器 |
| 安装失败 9568289 | 装了 unsigned hap 或签名不匹配 | 用 `*-signed.hap` |
| 模拟器黑屏 | Hyper-V 与其他虚拟机冲突 | 关掉 VMware/VirtualBox 再启动 |
| `git push` 报 502 / CONNECT 失败 | 代理节点对 github.com 不可用 | 走 SSH（见第 8 节） |
| 测试 0 条 | `List.test.ets` 未引用 | 确认 `fogEngineTest()` 在 `testsuite()` 里 |
| Git Bash 下 `hdc file recv` 路径异常 | MSYS 路径转换 | 命令前 `export MSYS_NO_PATHCONV=1` |
