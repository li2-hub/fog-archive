# 签名与模拟器操作步骤（Windows / DevEco Studio 5.0.13）

> 目标：让工程能签出可安装的 HAP，并在模拟器上真正执行 T1–T8 单测、留下截图。

## 0. 先确认版本对得上

| 项 | 你机器上的实际情况 |
|---|---|
| DevEco Studio | 5.0.13.240（`F:\DevEco Studio`） |
| SDK | HarmonyOS 5.0.5 / API 17（`F:\DevEco Studio\sdk`） |
| 工程 targetSdk / compatibleSdk | 5.0.5(17) |
| 现成模拟器实例 | `F:\HUAWEImoniqi\Huawei_Phone`，**HarmonyOS 5.0.5(17)**，x86_64，与工程完全匹配 |

注意：`C:\Users\Administrator\AppData\Local\Huawei\Emulator\deployed` 下那几个（Pura 90 Pro、Mate X7 等）是 DevEco 26 建的 **API 26** 实例，且 `F:\DevEco Studio\sdk\system-image` 目录并不存在，多半已失效。**优先用 `Huawei_Phone`**。

---

## 1. 登录华为账号

1. DevEco Studio 右上角头像图标 → **Sign In**。
2. 浏览器里用华为账号登录，回到 IDE 等待右下角提示登录成功。

> 自动签名必须登录；模拟器下载镜像也需要登录并同意协议。

## 2. 打开自动签名

1. 菜单 **File → Project Structure…**（快捷键 `Ctrl+Alt+Shift+S`）。
2. 左侧选 **Project**，右侧切到 **Signing Configs** 标签页。
3. 勾选 **Automatically generate signature**（自动生成签名）。
4. 若弹出协议/提示，点 **Agree / OK**；IDE 会自动生成 `.p12`、`.cer`、`.p7b` 并填好密码。
5. 点 **OK** 关闭对话框。

**成功判据（两条都要满足）**

- `F:\AdvancedStateLab\build-profile.json5` 里 `signingConfigs` 从 `[]` 变成一个包含 `name: "default"`、`material` 字段的对象。
- 终端重新构建时，不再出现 `WARN: Will skip sign 'hos_hap'`。

> 现状解释：你的工程 `signingConfigs` 是空数组，但 product 里写了 `"signingConfig": "default"`，所以之前构建日志一直是 skip sign。

## 3. 启动模拟器

1. 菜单 **Tools → Device Manager**（或工具栏的设备图标）。
2. 切到 **Local Emulator / 本地模拟器** 页签，列表里应能看到 **Huawei_Phone**（HarmonyOS 5.0.5）。
3. 点它右侧的 **启动（三角形）**，等系统桌面出现（首次启动 1–3 分钟）。

**如果列表是空的**：

- 点 **… → 打开实例目录**，确认实例在 `F:\HUAWEImoniqi\Huawei_Phone`；
- 或直接 **New Emulator**：机型选 Phone → 系统镜像选 **HarmonyOS 5.0.5（API 17）** → 下载 → 完成。**不要选 API 26 镜像**，与工程 SDK 不一致会增加排查成本。

## 4. 确认设备已连接

```bash
export MSYS_NO_PATHCONV=1
HDC="/f/DevEco Studio/sdk/default/openharmony/toolchains/hdc.exe"
"$HDC" list targets
```

期望输出：`127.0.0.1:5555`（或 `emulator-5554`）。若为空，执行 `"$HDC" kill` 后重试；DevEco 右上角的设备下拉框里也应出现该设备。

## 5. 执行 T1–T8

### 方式 A：IDE 里跑（推荐，能直接看结果面板）

1. 打开 `entry/src/ohosTest/ets/test/FogEngine.test.ets`。
2. 点 `describe('FogEngine', ...)` 左侧的绿色三角 → **Run 'FogEngine'**。
3. 底部 **Test Result** 面板应出现 8 条：`T1_initial_state` … `T8_ending_branches`，全部绿色。

### 方式 B：命令行跑（可写进报告，证据更硬）

```bash
cd "F:/AdvancedStateLab"
export MSYS_NO_PATHCONV=1
HDC="/f/DevEco Studio/sdk/default/openharmony/toolchains/hdc.exe"

"$HDC" install -r entry/build/default/outputs/default/entry-default-signed.hap
"$HDC" install -r entry/build/default/outputs/ohosTest/entry-ohosTest-signed.hap

"$HDC" shell aa test -b com.example.campuscardlab -m entry_test \
  -s unittest OpenHarmonyTestRunner -s timeout 60000
```

期望结尾出现 `OHOS_REPORT_RESULT: stream=Tests run: 8, Failure: 0, Error: 0`（数字以实际为准，若含原有 Ability 用例会更多）。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 勾了自动签名仍提示失败 | 未登录 / 未同意协议 / 网络不通 | 重新登录，关掉代理后重试 |
| 构建仍 `Will skip sign` | `signingConfigs` 未写入 | 回 Project Structure 确认点过 OK，检查 `build-profile.json5` |
| `hdc list targets` 为空 | 模拟器没起 / hdc 服务卡住 | 等桌面出现；`hdc kill` 再 `list targets` |
| 安装报 `9568289 install failed` | HAP 未签名或签名与设备不匹配 | 用 `*-signed.hap`，确认是 API 17 模拟器 |
| 模拟器黑屏 / 起不来 | Hyper-V / WHPX 冲突 | 关闭其他虚拟机（VMware/VirtualBox），确认 Windows 功能里 Hyper-V 与虚拟机平台已启用 |
| 测试跑起来但 0 条 | `List.test.ets` 没引用 | 确认 `fogEngineTest()` 已加进 `testsuite()` |
| `aa test` 报 module 不存在 | 模块名写错 | 测试模块名是 `entry_test`（见 `ohosTest/module.json5`） |
| Git Bash 里 `hdc file recv` 路径变样 | MSYS 路径转换 | 命令前加 `export MSYS_NO_PATHCONV=1` |

## 8. 跑完告诉我这三件事

1. T1–T8 的实际通过数（或失败的用例名 + 报错行）；
2. 模拟器系统版本（`hdc shell param get const.product.software.version`）；
3. `hdc list targets` 的输出。

拿到这些我就接着做 M2：Preferences 存档 + T9，并开始出入口页与场景页的骨架。
