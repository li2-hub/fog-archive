## 1. 项目背景与目标

校园里发生一起"学生违规滞留被处分"的事件，但证据链存在明显缺口。玩家以学生记者身份，在三个场景中收集六条线索、完成两次推理，最终作出判断，走向"真相"或"误判"两个结局。

设计目标（对应四个课程目标）：

1. **能用 ArkTS 建业务模型**：剧情、线索、状态全部建模为强类型接口，业务规则集中在纯函数引擎中。
2. **能用 ArkUI 做真实交互**：多页跳转、条件化选项、线索板组合操作、状态驱动的动画反馈。
3. **能做数据持久化**：任意时刻杀进程，冷启动可回到原节点、原线索、原时间。
4. **能写自动化测试**：引擎 9 条用例覆盖正常、边界、异常与分支。

非目标（明确不做）：AI 生成剧情、在线服务端、多人联机、真实账号体系。

---

## 2. 用户与使用场景

- 角色：校学生记者站调查员（单一玩家，单机）。
- 典型流程：打开 App → 继续上次存档 → 选场景 → 触发事件 → 做选择 → 得线索 → 在线索板组合推理 → 进入最终判断 → 看结局与复盘 → 重开。
- 关键约束：一次完整通关 8–12 分钟；任何一步中断都不丢进度。

## 3. 功能需求

### FR-1 入口与存档管理
- FR-1.1 启动显示存档摘要（阶段、线索数、最后时间）；无档显示"开始调查"。
- FR-1.2 支持"继续""重新开始"；重开需二次确认。
- FR-1.3 存档损坏时提示并自动开新档，不崩溃。

### FR-2 场景探索与事件节点
- FR-2.1 提供 3 个场景：图书馆 B1、实验楼 403、体育场看台。
- FR-2.2 共 12 个事件节点，节点含标题、正文、阶段、前置条件、选项。
- FR-2.3 节点进入受前置线索/推论/标记限制，不满足时不可进入并给出原因。
- FR-2.4 选项可消耗时间、授予线索、设置或清除标记、跳转节点。
- FR-2.5 同一节点在不同状态下文案可不同（体现"选择改变后续"）。

### FR-3 线索板与推理
- FR-3.1 线索板展示 6 条线索，已获得可查看详情，未获得显示占位。
- FR-3.2 选择两条线索执行"验证推理"，命中组合生成推论并解锁后续。
- FR-3.3 推理失败给出明确失败反馈，不扣线索，可重试。
- FR-3.4 推论可被节点前置条件引用。

### FR-4 状态提示与进度
- FR-4.1 顶部 HUD 常驻显示：阶段名、已获线索数/6、推论数/2、剩余时间。
- FR-4.2 阶段进度条随 `stage` 动画推进（5 段）。
- FR-4.3 时间耗尽时禁止消耗型选择，只允许进入最终判断。

### FR-5 结局
- FR-5.1 结局 A「八分钟」：`d_gap` 且 `d_who` 且选择"提交完整证据链"且线索数 ≥ 5。
- FR-5.2 结局 B「替罪者」：其余全部情况。
- FR-5.3 结局页展示结局名、达成条件回放、线索收集率、推理完成度，提供"再来一次"。

### FR-6 数据持久化
- FR-6.1 每次状态变更后写入 Preferences（节流 500ms），`onBackground` 兜底写入。
- FR-6.2 冷启动从存档恢复完整状态（节点、线索、推论、标记、时间、阶段）。
- FR-6.3 存档带 `schemaVersion`，未知版本按损坏处理。

## 4. 模块划分与接口约定

分层与依赖：`pages/view → store → engine → model`，`model` 为叶子。

### 4.1 model 层（纯类型 + 静态剧情数据）

```ts
// Types.ets
export enum Stage { ACCEPT = 0, SURVEY = 1, VERIFY = 2, VERDICT = 3, ENDING = 4 }
export enum EndingId { NONE = 'none', TRUTH = 'A_8MIN', SCAPEGOAT = 'B_SCAPEGOAT' }

export interface ClueDef { id: string; name: string; summary: string; detail: string; sceneId: string; }

export interface ChoiceDef {
  id: string; label: string; nextNodeId: string;
  cost: number;
  requireClues?: string[]; requireFlags?: string[];
  denyText?: string;
  grantClues?: string[]; setFlags?: string[]; clearFlags?: string[];
}

export interface StoryNode {
  id: string; sceneId: string; title: string; text: string; stage: Stage;
  requireClues?: string[]; requireDeductions?: string[]; requireFlags?: string[];
  enterEffects?: { grantClues?: string[]; setFlags?: string[] };
  choices: ChoiceDef[];
}

export interface GameState {
  version: number;
  currentNodeId: string;
  stage: Stage;
  collectedClues: string[];
  deductions: string[];
  flags: string[];
  visitedNodes: string[];
  timeLeft: number;
  turn: number;
  endingId: EndingId;
  startedAt: number;
  updatedAt: number;
}

// StoryGraph.ets
export const NODES: Record<string, StoryNode>;
export const CLUES: Record<string, ClueDef>;
export const SCENES: SceneDef[];
export const DEDUCTIONS: DeductionDef[];   // { id, requires: [clueA, clueB], conclusion }
export function nodeById(id: string): StoryNode;
export function clueById(id: string): ClueDef;
```

### 4.2 engine 层（纯函数，无 UI / 无 IO）

```ts
// GameEngine.ets
export function createInitialState(now: number): GameState;
export function canEnter(node: StoryNode, state: GameState): EnterResult;      // { ok, reason }
export function isChoiceAvailable(choice: ChoiceDef, state: GameState): ChoiceAvailability;
export function applyChoice(state: GameState, choice: ChoiceDef, now: number): GameState;
export function advanceStage(state: GameState): GameState;

// Deduction.ets
export function tryDeduce(state: GameState, clueA: string, clueB: string): DeduceResult;
// { ok, deductionId?, conclusion?, reason? }

// EndingResolver.ets
export function resolveEnding(state: GameState, finalChoice: FinalChoice): EndingId;
export function endingDetail(id: EndingId): EndingDetail;
```

约定：
- 所有函数**不修改入参**，返回新对象（便于单测与撤销式调试）。
- 失败路径返回结构化原因，不抛异常；只有编程错误才 `throw`。
- 不依赖 `Context`，时间通过参数注入（`now`），保证可测。

### 4.3 store 层

```ts
// SaveRepository.ets
export class SaveRepository {
  constructor(ctx: common.UIAbilityContext);
  async load(): Promise<GameState | null>;      // 损坏返回 null 并备份原始串
  async save(state: GameState): Promise<void>;
  async clear(): Promise<void>;
}

// GameStore.ets
@Observed
export class GameStore {
  state: GameState;
  revision: number;
  dispatch(choiceId: string): DispatchResult;   // 内部调用 engine + 触发存档
  deduce(a: string, b: string): DeduceResult;
  restart(): void;
}
```

## 5. 数据模型

### 5.1 实体关系

```
Scene 1 ── n StoryNode 1 ── n ChoiceDef
StoryNode n ── n ClueDef        （requireClues / grantClues）
ClueDef  n ── n DeductionDef    （requires 两条线索）
GameState 1 ── 1 SavePayload    （Preferences: fog_archive / save_v1）
```

### 5.2 存档结构

```json
{
  "schemaVersion": 1,
  "state": {
    "version": 1, "currentNodeId": "n_b1_tape", "stage": 1,
    "collectedClues": ["c_log", "c_door", "c_tape"],
    "deductions": ["d_gap"], "flags": ["accepted"],
    "visitedNodes": ["n_accept", "n_gate", "n_b1_door"],
    "timeLeft": 390, "turn": 5, "endingId": "none",
    "startedAt": 1731800000000, "updatedAt": 1731800900000
  },
  "checksum": "…"
}
```

### 5.3 关键规则表

| 规则 | 表达式 |
|---|---|
| 节点可进入 | `requireClues ⊆ collectedClues ∧ requireDeductions ⊆ deductions ∧ requireFlags ⊆ flags` |
| 选项可用 | 节点可进入 ∧ `cost ≤ timeLeft` ∧ 选项前置满足 |
| 推理成立 | `{clueA, clueB} = deduction.requires`（顺序无关） |
| 结局 A | `d_gap ∈ deductions ∧ d_who ∈ deductions ∧ finalChoice = SUBMIT ∧ |clues| ≥ 5` |
| 结局 B | `¬结局A` |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 冷启动到入口页 < 1.5s；页面切换 < 300ms；存档写入不阻塞 UI |
| 可靠性 | 任意时刻杀进程不丢最后一次已提交状态；损坏存档不崩溃 |
| 可用性 | 选项置灰必须说明原因；空态/异常态均有文案 |
| 兼容 | 适配深色模式；手机竖屏为主，平板不破版 |
| 可测性 | 引擎零 IO 零 UI 依赖；时间可注入 |
| 代码规范 | 通过 `code-linter.json5`；禁止 `any`；命名 `FogXxx` 前缀避免与实验代码冲突 |
