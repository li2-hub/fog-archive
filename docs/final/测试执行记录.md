## 一次真实缺陷与修复（可写进报告）

首次执行结果为 **8 通过 / 1 失败**：

```
Error in T4_clue_grant_is_idempotent, expect 0 equals 1
```

原因：T4 用全新状态直接跳到 `n_b1_shelf` 领取线索，而该选项的目标节点 `n_b1_tape`
要求前置线索 `CLUE_DOOR`（门禁记录），于是被引擎的 `canEnter` 守卫拦下，
`applyChoice` 返回 `ok=false`，线索数仍为 0。

判定：**引擎行为正确，测试用例的准备步骤缺失**。修复方式是把用例的前提补齐
（预置 `CLUE_DOOR`），并新增 `GameState.countClue()` 直接断言"同一条线索只被记录一次"，
让该用例只验证幂等性这一件事。修复后 9/9 通过。

这条"先失败、再定位、再修复"的记录比一次全绿更能说明测试是真的在跑。
